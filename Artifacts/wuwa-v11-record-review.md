## 结论

新增的直接呈现入口记录有效。1314 次原游戏呈现确认，1312 个原帧与插帧层呈现完整配对，零原游戏未确认呈现、零记录丢失、零帧序错误。

**原游戏已呈现到插帧层再次呈现，同帧 P50 为 41.67 ms；游戏请求呈现到插帧层呈现，同帧 P50 为 69.22 ms。** 后者不包含游戏之前的输入、逻辑和渲染，不是输入到屏幕的总延迟。它直接按每个原帧计算，不是相加阶段 P50 得到的估计。

当前 captureRoutes 全部为 directAfterPresented。我们在原游戏 drawable 呈现回调中才启动捕获，因此面板的捕获到显示约 41.39 ms 没有包含前面原游戏的呈现等待。原层可能被插帧层覆盖，其呈现确认也不等于该原层像素被用户看见。

## 下一步低时延方向

优先研究直接呈现路径的 **提前安全捕获**：将最终写入该 drawable 的游戏 GPU command buffer 与纹理配对，在游戏 GPU 完成后就启动复制/转换，而不是等 drawable 的呈现确认。当前直接呈现入口不知道原游戏 GPU 完成时间，不能单凭 present 调用就假定纹理可读。

候选应只对能够可靠配对并证明 GPU 写入完成的帧启用快路径；未识别路径保留呈现后捕获回退。同时记录 GPU 完成到捕获、两层同帧增量、快路径覆盖率和回退原因。取得实际同步信号后，才可能把捕获和插帧与原游戏的呈现等待重叠。

本轮证据证明现有路径串行等待原游戏呈现，但没有证明这 27 ms 可以全部省掉，也不能承诺最终达到某个延迟。原游戏 GPU 完成时刻仍未测出，且提前捕获将改变回压和游戏提交节奏。

随后再在新捕获路径上按每对 AB 帧余量微调调度与中间帧过期保护，比较同源呈现增量 P50/P95、原游戏帧率、唯一输出 fps、插帧交付率、帧序及最长回退；不能只看面板 P50 数字。
