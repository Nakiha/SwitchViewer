# 游戏运行中配置切换验收

日期：2026-10-07。Apple M5、macOS 27、120 Hz 桌面，真实 Metal 测试窗口与
Apple 插帧输出。测试不会启动用户的真实游戏；结果不代表鸣潮自身渲染负载或
手柄到屏幕时延。已经加载旧库的游戏仍需首次重新启动才能使用配置通道。

## 运行中切换与失败回退

- 完整 UI 流程通过 159 项检查，包括同一 PID 中 2× → 4× → 8× → 2× 的切换、
  0 ms / 自动预算、720p / 1080p、同步与显示节奏、连续修改合并及实际呈现确认。
- 在开启逐帧诊断的情况下确认配置应答不会被日志积压阻塞；读取有单次批量上限，
  不无限占用主队列。
- 暂停插帧后修改配置仍保持原画面；恢复后继续运行。切换后双路录制完成，包含
  原始帧和确认呈现的生成帧；录制期间五类配置均锁定，调用层也拒绝写入。
- 模拟新会话创建失败的独立检查通过 16 项：旧配置与游戏进程保留、选择回滚、
  呈现恢复，然后再次成功切换。故障开关只在测试窗口进程生效。
- Swift 100 项测试、诊断分析 Python 13 项测试通过。新增协议测试覆盖完整配置的
  原子编码、非法输入、不同启动通道隔离与状态合并、倍率降低时帧编号持续递增。
  最终逐帧记录还检查了 7 个切换边界及 574 个原帧编号，生成帧编号没有与原帧重叠。

## 默认 2× 性能对照

基线为 `dd297bc` 的发布构建，与本次发布构建交替运行两轮，每轮 12 秒。
30 fps 输入、720p 代理、关闭垂直同步、均匀显示节奏，排除启动预热及末尾未排空日志。

| 指标 | 基线两轮 | 本次两轮 |
| --- | --- | --- |
| 实际呈现 | 60.04 / 59.91 fps | 60.03 / 60.04 fps |
| 原帧呈现率 | 99.61 / 99.61% | 99.23 / 99.61% |
| 原帧参考年龄 P95 | 40.58 / 44.50 ms | 40.16 / 42.01 ms |
| 处理就绪 P95 | 12.21 / 11.59 ms | 12.02 / 12.17 ms |
| 呈现间隔 P95 | 25.00 / 25.00 ms | 25.00 / 25.00 ms |

四轮帧顺序错误、过期提交均为 0。原帧参考年龄 P95 两轮均值约从
42.54 ms 到 41.08 ms；两轮均值增加不超过 2 ms、原帧呈现率减少不超过
1 个百分点的检查通过。默认 2× 没有发现超出上述容差的退化，不能由此推断
任意设备或负载下完全相同。
