# 屏幕捕获的内容时间线插帧

2026-09-30。游戏窗口和显示器捕获自动启用；采集卡继续使用原有 Switch 周期识别。

## 行为

- 识别捕获画面的独立更新，不要求固定 60Hz 或 30/40fps 重复周期。ScreenCaptureKit idle 重放和采样签名相同的画面不再送插帧。
- 重复画面不推进上一张独立画面的时间戳。中间帧使用相邻独立画面时间戳的中点。
- 画面更新率是最近 24 个独立更新间隔的次数/时间。它表示观察到的捕获内容更新率，不是直接读取游戏引擎 FPS；捕获限制和 UI 动画可能影响读数。
- 暂停超过 150ms、格式变化、明显的全画面亮度切换，不跨边界做插值。
- 屏幕捕获通过独立时间线定时呈现，每次提交一张帧。初始延迟预算 50ms，依据插帧就绪时间和渲染耗时调整，上限 100ms。过期的中间帧被丢弃；不回退显示旧时间戳。
- 游戏操作模式切到其他应用时暂停处理隐藏的预览，恢复游戏焦点后继续。
- 日志将原有帧率计数标为 submittedFPS，并新增实际显示帧率、屏幕内容更新率、迟到/过期丢帧和时间线延迟。

## 验证

- Release 构建通过。
- 四项 XCTest 通过：带重复和时间抖动的 30fps、原生 60fps 和变化的更新间隔、暂停/切场/尺寸/时钟变化、处理中释放 Apple 插帧器。
- 独立编译生产定时器及帧类型做时间线检查：8 张源帧和 7 张中间帧按媒体时间排序，切换代次后旧帧被拒绝。时间线允许丢弃实际迟到的中间帧。
- 可控移动画面：30fps 阶段实际显示约 60fps；约 58 次/秒更新的阶段实际显示约 112–115fps；不规则更新阶段约 77–79fps。窗口和原生全屏覆盖均测试。
- 鸣潮当前场景：观察到约 38–42 次/秒内容更新，实际显示约 76–79fps。仅代表当前场景，未执行战斗或大幅转镜头的性能测试。

测试日志：`.build/screen-timing-check/log/switchviewer.log`、`.build/screen-timing-check/game-log/switchviewer.log`。
Apple 中间帧自身的软化、UI 光流伪影需要另行评估；本次调整针对更新识别、帧配对和显示节奏。
