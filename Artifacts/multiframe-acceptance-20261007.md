# 多倍插帧配置验收

日期：2026-10-07。Apple M5，macOS 27，120 Hz 桌面，30 fps Metal 测试窗口。
这是实际 Apple 插帧与 drawable 呈现检查，不是只用耗时公式回放。
测试窗口不包含真实游戏的渲染负载，不代表手柄到屏幕时延，也不代表所有设备结果。

## 默认 2× 对照

基线：`dd297bc`。两轮交替运行旧版与新版，每轮 12 秒，排除开始 3 秒的会话预热
和结尾未排空的诊断窗口。输入、720p 代理、垂直同步、显示节奏和测试窗口相同。

| 指标 | 旧版两轮 | 新版两轮 |
| --- | --- | --- |
| 实际呈现 fps | 59.79 / 59.91 | 60.03 / 60.03 |
| 原始帧呈现率 | 99.61% / 99.61% | 99.61% / 99.61% |
| 原帧参考年龄 P95 | 44.77 / 43.39 ms | 45.56 / 40.54 ms |
| 处理就绪 P95 | 11.29 / 11.97 ms | 11.73 / 12.58 ms |
| 呈现间隔 P95 | 33.33 / 25.00 ms | 25.00 / 25.00 ms |

默认 2× 继续使用原单帧输出回调和呈现仲裁。新增诊断字段不进入默认 2× 的逐帧
序列化工作量。对照检查以两轮分位数均值不增加超过 2 ms、原帧呈现率不减少超过
1 个百分点为容差；检查通过。显示结果仍有刷新周期与测试轮次波动，不能宣称任意
负载下逐帧完全相同。

## 多倍与预算

| 配置 | 实际呈现 fps | 原始帧 fps | 主动缓冲 P95 | 原帧参考年龄 P95 |
| --- | --- | --- | --- | --- |
| 720p，4×，60 ms | 119.96 | 30.02 | 48.29 ms | 67.05 ms |
| 720p，8×，80 ms | 120.07 | 30.02 | 47.52 ms | 74.17 ms |
| 1080p，8×，60 ms，过载 | 48.55 | 30.01 | 60.00 ms | 76.96 ms |
| 720p，4×，0 ms | 30.01 | 30.01 | 2.86 ms | 26.27 ms |

「主动缓冲」列从原始帧进入到其呈现目标计算。0 ms 情况仍包含转换与回调实际
完成所需的约 2.86 ms，不再生成无法使用的插值帧。真实呈现参考年龄还包含后续
GPU / 呈现等待，因此数值可以超过配置预算；界面与使用文档明确区分这两项。

4× 三个位置均被生成并显示。8× 七个位置均被生成，120 Hz 屏幕只显示部分输出，
实际最高仍约 120 fps。过载时不积压 Apple 请求，也不自动更改用户所选倍率；原始
帧继续约 30 fps，插值帧超过自己的时间槽便丢弃。上述场景均无序号倒退和过期提交。
本检查没有要求物理上屏时间绝对不超过提交槽：系统仍可能延后已提交的 drawable。

## 回归与构建

- Swift：96 项通过，包含真实 GPU 的 2× / 4× / 8× 输出与请求期间释放所有者检查。
- Python：13 项通过，包含多倍帧角色、倍率与后继原始帧的诊断关联。
- 桌面工作流：118 项通过，包含独立配置、0 ms 预算与恢复默认设置。
- 采集多输出：19 项通过，三个位置分别回调，并保留完整源间隔和正确帧时长。
- macOS Release 构建与严格签名校验通过；iPad 真机 / 模拟器构建通过。
- 人工查看新增配置的原生面板，选项与数字输入无重叠或裁切。

复现入口：`Scripts/check-multiframe-playout.py`、`Scripts/check-ui-workflow.sh`。
