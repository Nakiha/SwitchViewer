# 录制对比素材

为演示视频提供一次操作的两路素材，不需要分别重复游戏动作。在运行面板的「工具」页点击「录制对比素材」，回到游戏保持镜头运动，再点击「停止录制」；最长 30 秒自动停止。等到「两路素材已保存」后点击「打开素材」。鸣潮需要从新构建的 SwitchViewer 重新启动，才能加载录制模块。

输出文件：

- `original.mov`：进入插帧管线的原始采集帧。
- `processed.mov`：包含原帧与生成帧的处理后素材，仅记录系统确认呈现的帧。
- `recording.json`：共同时间原点、素材起始时间、写入帧数、生成帧数、录制器丢帧数和完成状态。异常退出可能留下 `recording` 或 `incomplete` 状态，应重新录制。

两路使用相同的源内容时间轴，保留可变帧率；插帧的时间戳位于对应源帧对的中点。文件起始位置可能包含空白时间，剪辑时根据时间轴共同裁切，不能分别把第一张画面移到零点。建议先录 10～15 秒，确认两路都有运动和生成帧。

画面统一放进 1920×1080、H.264 的 MOV，按源画面比例缩放并留黑边。Mac 采集模式保存在 `~/Movies/SwitchViewer/`；沙盒游戏保存在它自己的可写 Movies 目录，使用「打开素材」定位。

当前功能仅录画面，不录音频或工具栏。素材取自最终显示着色前的帧缓冲，未包含显示着色器的原帧柔化或手动色彩覆盖；使用默认色彩、关闭「降低原帧清晰度以匹配插帧」适合做对比。它展示帧内容的变化，不还原屏幕的实际显示间隔、撕裂或操作延迟。需要证明这些效果时应另录屏幕或用外部相机。

两路编码和缩放会增加负载。后台队列最多保留 8 帧；编码器繁忙时丢弃录制帧而不等待游戏，丢弃数量写入 JSON。生成失败或没有录到生成帧不会提示成功。素材不用于证明未录制时的性能，录制前后性能数据应另行测量。

停止录制并保存后再退出游戏。切换采集源会结束当前素材；退出 SwitchViewer 时会先完成本地录制，游戏内录制则发送停止请求并由仍在运行的游戏保存。强制结束进程可能损坏未完成的视频。
